NETWORK MODELS

Physical vs Logical Communication

การสื่อสารมี 2 มุมมอง — มุมมองทางกายภาพ (เส้นจริง) กับมุมมองเชิงตรรกะ (เส้นทางที่ข้อมูลเดินทาง)

Physical — ทางกายภาพ

เส้นทางที่สัญญาณไหลผ่านจริง เช่น สายทองแดง ใยแก้ว คลื่นวิทยุ เป็นการเชื่อมต่อของอุปกรณ์ในแต่ละช่วง (hop)

💻📡📡🖥️

💡 ดูที่สายไฟและอุปกรณ์ที่ข้อมูลไหลผ่านจริง

Logical — เชิงตรรกะ

เส้นทางเชิงตรรกะที่ข้อมูลเดินทางจากต้นทางถึงปลายทาง ข้ามหลายเครือข่าย เหมือนเส้นทางที่ GPS วางแผนไว้ — ไม่ใช่สายจริงเส้นเดียว

ABCD

💡 ดูที่ต้นทาง → ปลายทาง โดยไม่สนใจสายระหว่างทาง

จำแบบนี้Physical = ถนนจริงที่รถวิ่ง · Logical = เส้นทางที่ GPS วางแผนให้รถไปถึงจุดหมาย
Exam Tipข้อสอบชอบถาม "ข้อใดคือ Physical Communication" — ให้มองหาคำตอบที่เกี่ยวกับสายไฟ/คลื่นสัญญาณ ส่วน Logical จะเกี่ยวกับเส้นทางและ IP

End Systems / Hosts

อุปกรณ์ปลายทางที่ผู้ใช้ใช้โดยตรง — คอมพิวเตอร์ มือถือ แท็บเล็ต หรือเซิร์ฟเวอร์ อยู่ที่ขอบเครือข่าย (Edge)

Clients & Servers

Client = ผู้ร้องขอบริการ (เช่น เบราว์เซอร์) · Server = ผู้ให้บริการ (เช่น เว็บเซิร์ฟเวอร์) — ทั้งคู่เป็น End System

Access Networks

เครือข่ายที่เชื่อม End Systems เข้าสู่แกนกลาง เช่น Wi-Fi ที่บ้าน, Fiber/ADSL, โมบาย 4G/5G

Exam Tipถ้าข้อสอบถาม "ข้อใดคือ End System" — ตอบคอมพิวเตอร์/มือถือ/เซิร์ฟเวอร์ (อุปกรณ์ที่อยู่ขอบ) ไม่ใช่ Router หรือ Switch (อยู่กลางเครือข่าย)

OSI vs TCP/IP — ต่างกันยังไง?

OSI เป็น โมเดลอ้างอิง (Reference Model) ที่ออกแบบโดย ISO แบ่งละเอียด 7 ชั้น เพื่อใช้อธิบายแนวคิด ส่วน TCP/IP เป็นชุดโปรโตคอลที่ Internet ใช้จริง — รวมชั้น Session, Presentation เข้าไว้ใน Application จึงเหลือ 5 ชั้น (หรือบางตำราแบ่ง 4 ชั้น)

จำแบบนี้OSI = 7 ชั้น อธิบายสวย ๆ (ทฤษฎี) · TCP/IP = 5 ชั้น ใช้จริงบน Internet (ปฏิบัติ)

DATA IN TRANSIT

PDU — Protocol Data Unit

ข้อมูลที่วิ่งผ่านแต่ละชั้นจะถูกเรียกชื่อต่างกันตามชั้นที่ดูแล — PDU = ข้อมูล + Header ของชั้นนั้น

PDU CHAIN · ชื่อข้อมูลเปลี่ยนไปทุกชั้น
ApplicationData
TransportSegment
NetworkPacket
Data LinkFrame
PhysicalBits

PDU คืออะไร?

Protocol Data Unit — ชุดข้อมูลที่แต่ละชั้นจัดการ ซึ่งรวม Header ของชั้นนั้นกับข้อมูล (Payload) ที่ส่งต่อลงมา ยิ่งลงล่าง ยิ่งถูกห่อเพิ่ม

จำลำดับยังไง?

จำจากบนลงล่าง: Data → Segment → Packet → Frame → Bits และย้อนกลับตอนรับข้อมูล (Bits → ... → Data)

Exam Tipข้อสอบชอบให้จับคู่ PDU กับ Layer: Segment=Transport · Packet=Network · Frame=Data Link · Bit=Physical — จำคู่เหล่านี้ให้แม่น

Encapsulation (ห่อ)

ตอนส่ง: แต่ละชั้นเพิ่ม Header ของตัวเองต่อหน้าข้อมูล จากบนลงล่าง — ข้อมูลยิ่งลงล่างยิ่งใหญ่ขึ้น

De-encapsulation (แกะ)

ตอนรับ: แต่ละชั้นถอด Header ของตัวเองออก จากล่างขึ้นบน — จนเหลือ Data บริสุทธิ์ส่งขึ้นไปถึงแอป

จำแบบนี้ห่อตอนส่ง (ลง) · แกะตอนรับ (ขึ้น) — เหมือนซองจดหมายที่ถูกซ้อนหลายชั้น
Exam Tipข้อสอบมักถาม "ลำดับ Encapsulation" — ตอบจากบนลงล่าง (Application → Physical) และ De-encap ย้อนกลับ

DATA IN TRANSIT

Header — ส่วนหัวของข้อมูล

ทุกครั้งที่ห่อข้อมูล จะมีการใส่ Header ที่บอก "ข้อมูลสำคัญสำหรับการส่ง" — เนื้อหาจริงเรียกว่า Payload

FRAME STRUCTURE · คลิกแต่ละส่วนเพื่อดู
Payloadข้อมูลจริง (Data)

— กดที่ส่วนของเฟรมเพื่อดูรายละเอียด —

Header เก็บอะไรบ้าง?

ที่อยู่ต้นทาง-ปลายทาง (IP/MAC), หมายเลขพอร์ต, หมายเลขลำดับ (Sequence), Checksum ตรวจความถูกต้อง และอื่น ๆ ตามแต่ละโปรโตคอล

Payload คืออะไร?

เนื้อหาข้อมูลจริงที่ต้องการส่ง (เช่น ไฟล์, ข้อความ) — ส่วน Header เป็นเพียง "ป้ายกำกับ" ที่ช่วยให้ส่งถึงที่ถูกต้อง

จำแบบนี้Header = ซองจดหมาย (ที่อยู่) · Payload = ตัวจดหมาย (เนื้อหา)

PROTOCOL & SERVICE

Protocol vs Service

Protocol คือ "กฎ" ส่วน Service คือ "ผลลัพธ์ที่ได้รับ" — สองอย่างนี้ไปด้วยกันเสมอ

Protocol — กฎ

ชุดกฎที่ว่าข้อมูลจะถูกส่งอย่างไร เช่น TCP (ส่งครบ เชื่อถือได้), IP (มีที่อยู่), HTTP (รูปแบบเว็บ) — เปรียบเหมือน "มารยาทและภาษา"

TCPUDPIPHTTPDNS

Service — บริการที่ได้รับ

สิ่งที่ชั้นบนได้รับจากชั้นล่าง เช่น "ส่งข้อมูลให้ครบถ้วน" (จาก TCP), "มีที่อยู่และเส้นทาง" (จาก IP), "เปิดเว็บได้" (จาก HTTP)

ส่งครบถ้วนมีที่อยู่เปิดเว็บได้แปลงชื่อโดเมน

อุปมาอุปไมย: การโทรศัพท์

Protocol = ภาษาที่เราใช้คุยและมารยาท (พูดทีละคน รอฟังอีกฝ่าย) · Service = ผลลัพธ์ที่เราได้รับ คือ "ได้สนทนากัน" — กฎทำให้บริการเกิดขึ้นได้

Exam Tipข้อสอบอาจถาม "TCP ให้บริการอะไร" — ตอบว่าบริการส่งข้อมูลแบบเชื่อถือได้ (Reliable Delivery) เพราะ TCP เป็น Protocol ที่ให้ Service นี้
