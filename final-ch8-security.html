FOUNDATIONS · SECURITY GOALS

Network Security คืออะไร

network security ไม่ได้มีแค่การเข้ารหัส — source วางเป้าหมายไว้ 4 ข้อที่ต้องมองพร้อมกัน

Confidentiality

เฉพาะ sender และ intended receiver เท่านั้นที่ควรเข้าใจเนื้อหา message

กลไกsender encrypts; receiver decrypts

Authentication

sender และ receiver ต้องการยืนยัน identity ของอีกฝ่าย

คำถามอีกฝ่ายเป็นใครจริง ๆ?

Message Integrity

ต้องการให้แน่ใจว่า message ไม่ถูกแก้ไขทั้งระหว่างส่งหรือภายหลัง โดยไม่ถูกตรวจพบ

Access & Availability

services ต้องเข้าถึงและใช้งานได้โดยผู้ใช้

เป้าหมายคำถามที่ตอบภัยที่เกี่ยวข้อง
Confidentialityใครอ่านข้อความได้?eavesdropping
Authenticationอีกฝ่ายเป็นใคร?impersonation / spoofing
Message integrityข้อความถูกแก้หรือไม่?message insertion / tampering
Availabilityบริการยังใช้ได้ไหม?denial of service
มองเป็นชุดการเข้ารหัสอย่างเดียวตอบ confidentiality แต่ไม่ได้ยืนยัน identity หรือกันการเล่นซ้ำโดยอัตโนมัติ

AES เป็น symmetric-key NIST standard ที่มาแทน DES ในเดือนพฤศจิกายน 2001 และใช้ block/key ขนาดใหญ่กว่า

AES specification

  • symmetric-key NIST standard
  • แทน DES (Nov 2001)
  • processes data in 128-bit blocks
  • key size: 128, 192 หรือ 256 บิต
149 trillion

PUBLIC KEY · REQUIREMENTS

Public-Key Requirements

public-key algorithm ต้องมีสมบัติทางคณิตศาสตร์ที่ทำให้เข้ารหัสแล้วถอดกลับได้ และทำให้การหา private key จาก public key เป็นไปไม่ได้ในทางปฏิบัติ

ข้อกำหนด

  1. ต้องมี K⁺(·) และ K⁻(·) ที่ทำให้ K⁻(K⁺(m)) = m
  2. เมื่อรู้ public key K⁺ ต้องเป็นไปไม่ได้ที่จะคำนวณ private key K⁻
Computationally infeasible ≠ Mathematically impossiblesecurity ของ public key ขึ้นกับความยากในการคำนวณ ไม่ใช่การพิสูจน์ว่าเป็นไปไม่ได้เชิงตรรกะ

Modular arithmetic

นิยามx mod n = remainder เมื่อหาร x ด้วย n
บวก[(a mod n)+(b mod n)] mod n = (a+b) mod n
ลบ[(a mod n)−(b mod n)] mod n = (a−b) mod n
คูณ[(a mod n)(b mod n)] mod n = (a·b) mod n
ตัวอย่าง sourcex=14, n=10, d=2 → (14 mod 10)² mod 10 = 4² mod 10 = 6; 14² mod 10 = 6

PUBLIC KEY · RSA MATH

RSA — Encryption & Decryption

RSA เข้ารหัส message ที่มองเป็นจำนวนเต็มด้วย public key (n,e) และถอดด้วย private key (n,d)

Encrypt

ciphertextc = m^e mod n
เงื่อนไขm < n

message ถูกมองเป็น bit pattern และแทนด้วยจำนวนเต็ม; encryption คือการยกกำลังแล้ว mod n

Decrypt

plaintextm = c^d mod n
ฟังก์ชันรวมm = (m^e mod n)^d mod n

ผู้รับใช้ private key d ที่ตรงกับ public key ที่ใช้เข้ารหัส

Why does RSA work?

ต้องแสดงว่าc^d mod n = m
เมื่อn = pq, z = (p−1)(q−1)
ได้ว่าc^d mod n = m^(ed mod z) mod n = m¹ mod n = m

TLS · SHARED KEY

Diffie-Hellman Key Agreement

Diffie-Hellman ให้ Alice และ Bob คำนวณ shared secret ได้โดยไม่ต้องส่ง secret นั้นตรง ๆ — แต่ใช้ algorithm คนละตัวกับ RSA

Public values

  • Bob เลือก large prime p และ g < p
  • Alice เลือก private value S_A
  • Bob เลือก private value S_B
  • Alice’s public key: K_A⁺ = g^S_A mod p
  • Bob’s public key: K_B⁺ = g^S_B mod p

Shared secret

Alice คำนวณ(K_B⁺)^S_A mod p
Bob คำนวณ(K_A⁺)^S_B mod p
ผลลัพธ์ค่าเท่ากัน

ทั้งสองฝ่ายคำนวณ common shared secret ได้เอง โดยไม่เคยส่ง secret นี้ผ่าน Internet

ใช้ใน TLSDiffie-Hellman เป็น key agreement protocol ที่ TLS 1.3 ต้องใช้สำหรับ key exchange ตาม source

TLS · HANDSHAKE

TLS 1.3 Handshake

TLS 1.3 ใช้ 1 RTT สำหรับ handshake ปกติ และรองรับ 0 RTT เมื่อ resuming connection — แต่ 0 RTT มีความเสี่ยง replay

—

—

1 RTT vs 0 RTT

1 RTT: client hello → server hello + certificate → client ตรวจ certificate และสร้าง key → ส่ง application request

0 RTT: initial hello มี encrypted application data; ใช้ “resumption master secret” จาก connection ก่อนหน้า; source ระบุว่า vulnerable to replay attacks — อาจ OK สำหรับ HTTP GET หรือ request ที่ไม่เปลี่ยน server state
