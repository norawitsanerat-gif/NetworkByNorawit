LINK LAYER · SERVICES

บริการหลัก 6 อย่าง

Framing/link access, reliable delivery, flow control, error detection, error correction และ duplex

Framing, link access

ห่อ datagram เป็น frame พร้อม header/trailer; shared medium ต้องมี channel access; ใส่ MAC address ของ source/destination

Reliable delivery

ส่งระหว่าง node ที่ติดกันให้ reliable ด้วย ACK/retransmission — มักใช้บน wireless ที่ error สูง

Flow control

ปรับจังหวะระหว่าง sender กับ receiver ที่ติดกัน ไม่ให้ผู้ส่งเร็วเกินผู้รับ

Error detection

ตรวจ error จาก attenuation/noise; ถ้าพบอาจสั่ง retransmission หรือทิ้ง frame

Error correction

ระบุตำแหน่งและแก้ bit error ได้เอง โดยไม่ต้อง retransmission

Half / Full duplex

half-duplex ส่งได้แต่ไม่พร้อมกัน; full-duplex ส่งพร้อมกันได้ทั้งสองทิศทาง

ไม่ใช่ทุก link ต้อง reliablesource ระบุว่ามักไม่ใช้ reliable delivery บน fiber/copper ที่ bit error ต่ำ แต่ใช้บน wireless ที่ error rate สูง
Framing ≠ IP addressingframe header มี MAC address ของ source/destination ซึ่งต่างจาก IP address ใน datagram

PARITY · SINGLE BIT

Even parity 1 บิต

เพิ่ม parity bit 1 บิตเพื่อให้จำนวน 1 ทั้งหมดเป็นเลขคู่ (even) หรือเลขคี่ (odd)

0111000110101011

ข้อมูลมี 1 อยู่ 9 ตัว (เลขคี่) → even parity เติม 1 ทำให้เป็น 10 ตัว (เลขคู่)

0111000110101011 1

ฝั่งรับ

  • นับจำนวน 1 ของ d บิตที่ได้รับ
  • คำนวณ parity แล้วเทียบกับ parity bit ที่ได้รับ
  • ถ้าไม่ตรง → ตรวจพบ error

ข้อจำกัด

  • บิตพลิก 2 ตำแหน่งอาจทำให้จำนวน 1 ยังเป็นเลขคู่ → ตรวจไม่พบ
  • ตรวจจับ error จำนวนคี่ได้ทั้งหมด แต่ error จำนวนคู่จะหลุด
  • ระบุตำแหน่งหรือแก้ไข error ไม่ได้
สรุปsingle parity = ง่ายมาก แต่แก้ error ไม่ได้ และไม่ Catch error จำนวนคู่

PARITY · 2D

Row + Column Parity

จัดข้อมูลเป็นตาราง i × j แล้วเพิ่ม row parity และ column parity — ลองคลิกบิตเพื่อจำลอง error

วิธีอ่าน

  • ถ้า parity ผิดที่แถว r และคอลัมน์ c → บิต (r,c) ผิด
  • แก้ single-bit error ได้โดยไม่ต้อง retransmission
  • ตรวจ 2–3 บิตได้ แต่แก้ไม่ได้
  • 4 บิตที่เป็นสี่เหลี่ยมมุมฉากอาจทำให้ parity ยังถูก → ตรวจไม่พบ

CRC · CONCEPT

Cyclic Redundancy Check

มองข้อมูลเป็น binary/polynomial แล้วหารแบบ modulo 2 — ซึ่งก็คือ XOR โดยไม่มีตัวทด

Ddata bits (k บิต)
Ggenerator r + 1 บิต
RCRC bits r บิต
ส่งD · 2^r XOR R
คำนวณR = remainder[(D · 2^r) / G]

ฝั่งส่ง

  1. นำ D · 2^r มาหารด้วย G แบบ mod 2 (XOR)
  2. เอาเศษ r บิตมาเป็น R
  3. ส่ง D ตามด้วย R

ฝั่งรับ

  1. รับ <D', R'>
  2. หารทั้งก้อนด้วย G
  3. เศษ 0 → ไม่พบ error; เศษไม่ 0 → ตรวจพบและทิ้ง frame
จำขนาดG มี r + 1 บิต → R มี r บิต · CRC เป็น detection ไม่ใช่ correction · mod 2 = XOR ไม่มี carry

CRC · PROPERTIES

CRC แข็งแรง กว่า checksum

CRC ตรวจจับ error ได้ดีโดยเฉพาะ burst error และ implement ใน hardware ได้เร็ว

คุณสมบัติ CRC

  • ตรวจจับ single-bit error ได้ทั้งหมด (ถ้า G มีอย่างน้อย 2 พจน์)
  • ตรวจจับ burst error ที่ยาว ≤ r บิตได้ทั้งหมด
  • burst ที่ยาวกว่า r อาจตรวจพบได้ขึ้นอยู่กับรูปแบบ
  • ถ้า G มี factor (x + 1) ตรวจจับ error จำนวนบิตคี่ได้ทั้งหมด
  • CRC-32 พลาดประมาณ 2^-32 หรือ 1 ใน 4.3 พันล้าน
  • Implement ด้วย shift register + XOR

MULTIPLE ACCESS · SHARED

Point-to-point vs Broadcast

Multiple access protocol ใช้เฉพาะ shared medium — point-to-point link ไม่ต้องมี

ประเภทลักษณะตัวอย่าง
Point-to-pointมี 2 node และ channel เฉพาะของตัวเองswitch กับ host, PPP สำหรับ dial-up
Broadcast / shared mediumหลาย node ใช้ medium เดียวกันEthernet เก่า, cable upstream, 802.11 WLAN, 4G/5G, satellite

MAC ที่ดี และ 3 ตระกูล

Ideal protocol ให้ throughput สูง fair decentralized และง่าย — แต่ protocol จริงต้องแลก

Ideal multiple access (R bps)

  • node เดียวต้องการส่ง → ใช้ rate R เต็ม

TDMA · FDMA · CDMA

แบ่ง channel เป็นชิ้นเล็ก ๆ แล้วจัดสรรให้ station ใช้แบบ exclusive → ไม่เกิด collision

TDMA

เข้าถึง channel เป็น rounds; แต่ละ station ได้ fixed-length slot; slot ที่ไม่มีใครใช้จะ idle

FDMA

แบ่ง spectrum เป็น frequency bands; station ได้ band คงที่; band ที่ว่างก็ idle

CDMA

RANDOM ACCESS · ALOHA

ALOHA 37% vs 18%

Random access ส่งที่ full rate โดยไม่ประสานงานล่วงหน้า — จึงเกิด collision และต้อง retransmit

Slotted ALOHA

  • frame ขนาดเท่ากัน; เวลาแบ่งเป็น slot = 1 frame
  • เริ่มส่งได้เฉพาะต้น slot; ทุก node synchronized
  • ชน → retransmit ใน slot ถัดไปด้วย probability p
  • p* = 1/N → max efficiency (1 − 1/N)^(N−1) → 1/e ≈ 0.37

ต้อง sync clock; มี collision และ idle slot

Pure (Unslotted) ALOHA

  • ไม่แบ่ง slot; frame มาถึง → ส่งทันที
  • frame ที่ t0 ชนกับช่วง [t0−1, t0+1]
  • vulnerable period = 2 frame times
  • max efficiency = 1/(2e) ≈ 0.18

RANDOM ACCESS · CSMA

ฟังก่อนส่ง แล้วหยุดเมื่อชน

CSMA ลด collision ด้วยการฟัง channel ก่อนส่ง; CSMA/CD ตรวจจับ collision ระหว่างส่งและหยุดทันที

CSMA

  • listen before transmit
  • channel ว่าง → ส่งทั้ง frame
  • channel ไม่ว่าง → defer
  • ยังชนได้เพราะ propagation delay ทำให้ไม่ได้ยินการส่งที่เพิ่งเริ่มของกันและกัน
  • เมื่อชน → เสียเวลาส่งทั้ง packet

CSMA/CD

  • ตรวจ collision ระหว่างส่ง
  • ตรวจพบ → abort การส่งทันที
  • ลดเวลาที่เสียไปกับ collision
  • ตรวจจับง่ายบน wired แต่ยากบน wireless
  • Wi-Fi ใช้ CSMA/CA ไม่ใช่ CSMA/CD

CSMA/CD · BACKOFF

Binary Exponential Backoff

หลัง collision ครั้งที่ m เลือก K จาก {0, …, 2^m − 1} แล้วรอ K × 512 bit times

ลำดับการทำงาน

  1. NIC รับ datagram แล้วสร้าง frame
  2. ตรวจ channel: idle → ส่ง; busy → รอจน idle
  3. ส่งจบโดยไม่พบการส่งอื่น → เสร็จ
  4. ระหว่างส่งพบการส่งอื่น → abort และส่ง jam signal
  5. เข้า binary exponential backoff แล้วกลับไปขั้น 2

MULTIPLE ACCESS · HYBRID

ผลัดกันส่ง และระบบจริง

Taking turns พยายามได้ข้อดีของ partitioning (load สูง) และ random access (load ต่ำ)

Polling

  • central controller เชิญ node ให้ส่งทีละตัว
  • มักใช้กับ device ที่ “โง่”
  • ข้อกังวล: polling overhead, latency, single point of failure
  • ตัวอย่าง: Bluetooth

Token passing

  • control token ส่งต่อตามลำดับ
  • node ที่ถือ token จึงส่งได้
  • ข้อกังวล: token overhead, latency, token หาย
  • ตัวอย่าง: Token Ring, FDDI

Cable Access Network (HFC) — ผสมหลายเทคนิค

  • Downstream: หลายช่อง FDM แบบ broadcast สูงถึง 1.6 Gbps ต่อ channel; CMTS ตัวเดียวส่งเข้า channel
  • Upstream: หลาย channel สูงถึง 1 Gbps ต่อ channel
  • ผู้ใช้ contend (random access) เพื่อแย่ง upstream time slots บางส่วน; slot อื่น assign แบบ TDM
  • DOCSIS: downstream MAP frame กำหนดว่า upstream slot ใดเป็นของใคร; คำขอใช้ random access + binary backoff
บทเรียนระบบจริงมัก ผสม channel partitioning กับ random access ไม่ได้ใช้แบบเดียวตลอด

VLAN · MOTIVATION

LAN เสมือน บน switch เดียว

LAN ใหญ่ขึ้น → broadcast หนัก และย้ายผู้ใช้ยาก — VLAN แก้ด้วยการแบ่ง LAN ทาง logical

ปัญหา 1 · Single broadcast domain

  • broadcast traffic layer 2 เช่น ARP, DHCP, unknown MAC วิ่งทั่ว LAN
  • เกิดปัญหา efficiency, security, privacy
  • เครือข่ายใหญ่ขึ้น → broadcast ยิ่งหนัก

ปัญหา 2 · Administrative issues

  • ผู้ใช้ CS ย้ายไปห้อง EE ที่ต่อ switch EE
  • แต่ยังต้องการอยู่ logically ในเครือข่าย CS
  • LAN แบนแบบเดิมทำได้ยาก

Port-based VLAN

switch ตัวเดียวตั้ง group พอร์ตเป็น VLAN ต่าง ๆ ได้ — ทำงานเหมือน switch เสมือนหลายตัว

  • Inter-VLAN forwarding ต้องใช้ routing (layer 3)
