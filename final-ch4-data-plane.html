NETWORK SERVICE MODEL

Service Model & Best-effort

“Network สัญญาอะไรกับ datagram ของเรา?” — Internet ตอบว่า best effort

Network ArchitectureService ModelBandwidthLossOrderTiming

Internet “best effort”

  • ไม่รับประกันว่า datagram จะส่งถึง destination สำเร็จ
  • ไม่รับประกันเรื่องเวลาและลำดับการส่ง
  • ไม่รับประกัน bandwidth ที่มีให้กับ end-to-end flow

ทำไม best-effort ถึงสำเร็จ?

  • กลไกเรียบง่าย → ถูกนำไปใช้อย่างแพร่หลาย
  • จัดสรร bandwidth ให้เพียงพอ
  • บริการแบบ replicated และ distributed ใน application layer
  • ควบคุม congestion ของบริการแบบ “elastic”

LONGEST PREFIX MATCHING · PRINCIPLE

Longest Prefix Matching — หลักการ

เมื่อหลาย entry match ได้ ให้เลือก prefix ที่ยาวที่สุด

เมื่อค้นหา forwarding table entry สำหรับ destination address ที่กำหนด ให้ใช้ address prefix ที่ยาวที่สุดซึ่ง match กับ destination address

ทำไมต้อง longest?

forwarding entries สามารถ overlap กันได้ — prefix ที่ยาวกว่าจะเจาะจงกว่า (more specific)

TCAM

มักทำด้วย ternary content addressable memories (TCAMs)

  • ส่ง address ให้ TCAM → ดึง address ออกมาได้ใน one clock cycle โดยไม่ขึ้นกับขนาด table
  • Cisco Catalyst: เก็บ routing table ประมาณ 1M entries ใน TCAM
Exam Tipถ้ามีหลาย prefix ที่ match อย่าเลือกอันแรก — ต้องเลือก prefix ที่ยาวที่สุด

DHCP · DYNAMIC HOST CONFIGURATION PROTOCOL

การได้มาซึ่ง IP Address — DHCP

host ได้ IP address จาก network server เมื่อ “เข้าสู่” network — ไม่ต้องตั้งค่าด้วยมือ

Goal

host ได้รับ IP address จาก network server แบบ dynamic เมื่อ “เข้าสู่” เครือข่าย

  • สามารถ renew lease ของ address ที่ใช้งานอยู่ได้
  • ทำให้ reuse address ได้ (ถือ address ไว้เฉพาะขณะเชื่อมต่อ/เปิดอยู่)
  • รองรับผู้ใช้เคลื่อนที่ที่เข้า/ออกเครือข่าย

ภาพรวม DHCP

  • host broadcast DHCP discover msg [optional]
  • DHCP server ตอบกลับด้วย DHCP offer msg [optional]
  • host ขอ IP address: DHCP request msg
  • DHCP server ส่ง address กลับ: DHCP ack msg

CHAPTER SUMMARY

สรุป 6 หัวข้อสำคัญของ Network Layer: Data Plane

Network Layer

ส่ง transport segment จาก sending → receiving host · router ตรวจ header และย้าย datagram จาก input → output

Data / Control Plane

data plane = local ต่อ router (ns) · control plane = network-wide (ms) · per-router algorithms หรือ SDN

Forwarding

forwarding table ในหน่วยความจำ input port · match plus action · destination-based forwarding

Longest Prefix Matching

เลือก prefix ที่ยาวที่สุดที่ match · TCAM ดึงข้อมูลได้ใน one clock cycle

IPv4 & Subnetting

address 32 บิตต่อ interface · subnet part = high-order bits · CIDR a.b.c.d/x

Router & IP in Action

switching fabrics · queuing/HOL · DHCP · route aggregation

ต่อไปคำถาม: forwarding table (destination-based forwarding) หรือ flow table (generalized forwarding) ถูกคำนวณอย่างไร? คำตอบ: โดย control plane (บทถัดไป)
