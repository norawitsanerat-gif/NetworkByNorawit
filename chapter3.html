SOCKETS & ADDRESSING

Process, Socket, IP Address และ Port

พื้นฐานที่เชื่อมไปสู่ Transport Layer — "ใคร" คุยกับ "ใคร" และรู้ได้ยังไงว่าต้องส่งให้ "ห้องไหน"

Process

โปรแกรมที่กำลังทำงานอยู่บนเครื่อง เช่น เบราว์เซอร์ที่เปิดอยู่คือ 1 process

Socket

"ประตู" ที่ process ใช้ส่ง/รับข้อมูลเข้า-ออกจากเครือข่าย — ข้อมูลเดินเข้า-ออกผ่านประตูนี้

IP Address

ที่อยู่ของเครื่อง (host) บนเครือข่าย — บอกว่า "บ้านหลังไหน"

Port Number

หมายเลขที่บอกว่า process ไหนบน host นั้นเป็นผู้รับ/ส่งข้อมูล — บอกว่า "ห้องไหนในบ้าน"

APP REQUIREMENTS

ความต้องการของ Application (Delay / Data Loss)

แต่ละแอปต้องการคุณสมบัติจากเครือข่ายไม่เหมือนกัน — หลัก ๆ พิจารณา 3 อย่าง

1. Data Loss

บางแอปทนไม่ได้เลย เช่น การโอนไฟล์ (หายนิดเดียวไฟล์เสียหาย) → ต้อง reliable · บางแอปทนได้บ้าง เช่น VoIP / วิดีโอสด (กระตุกนิดหน่อยยังใช้ได้)

2. Timing / Delay

บางแอปต้องการ Delay ต่ำมาก เช่น เกมออนไลน์, วิดีโอคอล (real-time) · บางแอปไม่ซีเรียส เช่น ส่งอีเมล

3. Throughput / Bandwidth

บางแอปต้องการแบนด์วิดท์ขั้นต่ำคงที่ เช่น สตรีมมิงวิดีโอ · บางแอปยืดหยุ่นได้ เช่น ดาวน์โหลดไฟล์

เลือกใช้ให้ถูก: TCP vs UDP
TCP — เน้นความน่าเชื่อถือ

ส่งครบ ตรวจสอบ รับประกันไม่หาย → ใช้กับโอนไฟล์, เว็บ, อีเมล (ยอมรับ Delay สูงกว่า)

UDP — เน้นความเร็ว / Delay ต่ำ

ส่งไว ไม่รับประกัน → ใช้กับเกม, วิดีโอคอล, สตรีมสด (ยอมรับการสูญเสียได้บ้าง)

จำง่ายเลือก TCP หรือ UDP ขึ้นอยู่กับความต้องการของแต่ละแอป: ทน loss ไม่ได้ → TCP · ต้องการ Delay ต่ำสุด → UDP

Stateless HTTP — เซิร์ฟเวอร์ไม่จำสถานะ

HTTP ถูกออกแบบให้เป็น stateless — เซิร์ฟเวอร์ไม่จำข้อมูลของ request ก่อนหน้า แต่ละ request ที่ client ส่งมาถือเป็นเรื่องใหม่ทั้งหมด เซิร์ฟเวอร์ไม่รู้ว่า request นี้กับ request ก่อนหน้ามาจากคนเดียวกันหรือเปล่า

💡 อยากให้จำสถานะ (เช่น ล็อกอิน) ต้องใช้กลไกเสริมอย่าง Cookies

อุปมาเหมือนพนักงานร้านที่ความจำสั้นมาก — ทุกครั้งที่คุณสั่งของ พนักงานจะถามข้อมูลใหม่หมด ไม่จำว่าคุณเพิ่งสั่งอะไรไป
จำ PortHTTP = 80 (ไม่เข้ารหัส) · HTTPS = 443 (เข้ารหัสด้วย TLS/SSL) — ออกสอบบ่อยมาก

HTTP CONNECTION & MESSAGE

Persistent vs Non-Persistent + โครงสร้าง HTTP Message

HTTP ใช้การเชื่อมต่อ TCP อย่างไร และข้อความที่ส่งไป-มากันมีหน้าตาแบบไหน

Non-Persistent

แต่ละ request/response ใช้ การเชื่อมต่อ TCP ใหม่ 1 ครั้ง แล้วปิดทันที — ถ้าหน้าเว็บมีหลายไฟล์ (รูป, CSS) ต้องเปิด-ปิด connection ใหม่ทุกไฟล์ → ช้า เพราะต้องทำ TCP handshake ใหม่ทุกครั้ง

Persistent

ใช้ การเชื่อมต่อ TCP เดียว ส่งหลาย request/response ต่อเนื่องกันได้ ไม่ต้องเปิด-ปิดใหม่ทุกครั้ง → เร็วกว่า ประหยัดเวลา handshake ซ้ำ ๆ — ค่า default ของ HTTP/1.1

GET vs POSTGET ส่งข้อมูลผ่าน URL (เช่น ?search=cat) เห็นข้อมูลง่าย ไม่เหมาะกับข้อมูลลับ · POST ส่งข้อมูลใน Body ของ request ไม่โชว์บน URL เหมาะกับข้อมูลยาว/อ่อนไหว เช่น รหัสผ่าน

DNS — DOMAIN NAME SYSTEM

DNS และ DNS Cache (สมุดโทรศัพท์ของอินเทอร์เน็ต)

คอมพิวเตอร์ต้องใช้ IP Address ในการส่งข้อมูล แต่มนุษย์จำชื่อได้ง่ายกว่า — DNS คือตัวแปลงระหว่างสองอย่างนี้

DNS LOOKUP · แปลงชื่อเป็น IP

DNS = สมุดโทรศัพท์

คุณจำชื่อเพื่อน (โดเมน) ได้ แต่จำเบอร์โทร (IP) ไม่ได้ — เมื่อจะโทร คุณเปิดสมุดโทรศัพท์ (DNS) เพื่อหาเบอร์ที่ตรงกับชื่อนั้น

DNS Cache

ทั้งเครื่องผู้ใช้และ DNS server ต่าง ๆ เก็บผลลัพธ์ที่เคยถามไว้ชั่วคราว — เมื่อถามชื่อเดิมซ้ำ จะดึงคำตอบจาก cache แทนการถามใหม่ตั้งแต่ต้น → เร็วขึ้นมาก และลดภาระ DNS server

📌 ข้อมูลใน cache มีอายุจำกัดตาม TTL (Time-To-Live) — หมดอายุแล้วต้องถามใหม่

จำDNS Cache ลด Delay และลดภาระของ DNS Server โดยรวม แต่คำตอบอาจล้าสมัยได้เมื่อมี TTL

SMTP

Simple Mail Transfer Protocol — ใช้ส่งอีเมล จากเครื่องผู้ส่งไป mail server และระหว่าง mail server ด้วยกัน (Port 25)

IMAP

ใช้รับ/ดึงอีเมลมาอ่าน — เก็บเมลไว้บนเซิร์ฟเวอร์ ดูจากเครื่องไหนก็เห็นเมลเหมือนกัน (Port 143)

POP3

ใช้รับ/ดึงอีเมล — ดาวน์โหลดเมลลงเครื่อง แล้ว (โดยค่าเริ่มต้น) ลบออกจากเซิร์ฟเวอร์ (Port 110)

จำSMTP = ส่ง (Port 25) · IMAP/POP3 = รับ (143 / 110) — ข้อสอบชอบจับคู่ "โปรโตคอลกับหน้าที่"

WELL-KNOWN PORTS

Port มาตรฐานที่สำคัญ (ต้องจำ!)

หมายเลขพอร์ตของบริการยอดนิยม — จำ 3 ตัวหลักก่อน: HTTP=80, HTTPS=443, DNS=53

เทคนิคจำเร็วจำ 3 ตัวหลักก่อนเป็นอย่างน้อย: HTTP=80 · HTTPS=443 · DNS=53 เพราะออกสอบบ่อยที่สุด แล้วค่อยเพิ่ม SMTP=25, FTP=20/21

สูตรจำก่อนสอบ — บทที่ 3

รวบรวมจุดที่ข้อสอบชอบถาม ฉบับย่อ เหมือนโน้ตสรุป

Client-Server→ Server กลางเปิดบริการ, Client ขอใช้บริการ
P2P→ ไม่มี Server ตายตัว, Peer คุยกันตรง ๆ
Process→ โปรแกรมที่กำลังทำงาน
Socket→ ประตูที่ Process ใช้ส่ง/รับข้อมูล
IP Address→ บ้านเลขที่ (เครื่องไหน)
Port Number→ เบอร์ห้อง (แอปไหนบนเครื่องนั้น)
HTTP→ Port 80 · ไม่เข้ารหัส
HTTPS→ Port 443 · เข้ารหัส TLS/SSL
Stateless→ Server ไม่จำ request ก่อนหน้า
Persistent→ ใช้ TCP เดียวส่งหลาย request (HTTP/1.1)
Non-Persistent→ เปิด-ปิด TCP ใหม่ทุก request
GET→ ขอดึงข้อมูล (ข้อมูลไปกับ URL)
POST→ ส่งข้อมูลเพื่อสร้างสิ่งใหม่ (อยู่ใน Body)
PUT→ ส่งข้อมูลแทนที่/อัปเดตทั้งหมด
DNS→ แปลงชื่อโดเมนเป็น IP (สมุดโทรศัพท์)
DNS Cache→ เก็บคำตอบไว้ชั่วคราว ลด Delay
SMTP→ ส่งอีเมล (Port 25)
IMAP / POP3→ รับ/ดึงอีเมล (143 / 110)
FTP→ โอนไฟล์ (Port 20/21)
HTTP Status→ 200 OK · 404 ไม่เจอ · 500 Server พัง
